# Phase 04: Secure Uploads

## Goal

Asset image uploads are validated by magic bytes with a jpeg|png|webp allowlist (SVG rejected), capped at 5 MB, stored outside `public/` under server-generated names, and served only through an authenticated route with path-traversal guards and validated headers. Closes the stored-XSS and disk-fill vectors.

**Mode**: mvp

## Requirements

- SEC-10: Upload gambar divalidasi magic bytes (file-type) dengan allowlist `jpeg|png|webp`; `image/svg+xml` ditolak
- SEC-11: Upload dibatasi ukuran 5 MB → 413; endpoint upload di-gate role (STAFF_ASSET minimum)
- SEC-12: File disimpan di luar `public/` (`<root>/uploads/assets/`) dengan nama acak server-side
- SEC-13: File disajikan via route terautentikasi dengan path-traversal guard, `Content-Type`/`Content-Disposition` tervalidasi, dan `nosniff`
- TEST-05: Test upload: svg ditolak, >5MB → 413, anonymous/employee → 401/403, tidak bisa diakses via URL statis

## Success Criteria (must be TRUE)

1. SVG / non-allowlisted types rejected; JPEG/PNG/WebP with valid magic bytes accepted.
2. Uploads > 5 MB → 413; anonymous → 401; below STAFF_ASSET → 403 (role gate already landed in Phase 2 — verify, keep).
3. Files stored outside `public/` — not reachable via any static URL; load only through the authenticated serve route.
4. Path-traversal attempts blocked; served responses carry validated `Content-Type`/`Content-Disposition` with `nosniff`.

## Design Decisions (pre-approved, document in summary)

- **No new dependency**: magic-byte validation is hand-rolled (JPEG `FF D8 FF`, PNG `89 50 4E 47 0D 0A 1A 0A`, WebP `RIFF`+`WEBP` at offset 8). `file-type` package would need a supply-chain approval the developer rejected in Phase 1 — hand-rolled for a 3-format allowlist is deterministic, zero-dep, and testable. SVG has no matching magic → rejected.
- **Storage**: `<root>/uploads/assets/<uuid>.<ext>` — project root, outside `public/`. Extension derived from detected magic bytes, never from client filename/type.
- **DB `imagePath`**: store the internal relative path `uploads/assets/<uuid>.<ext>` (no leading slash). Serve route maps it. If any client renders it, add a tiny mapping helper.
- **Legacy files**: leave `public/uploads/assets/` + legacy DB rows untouched (still statically served). New uploads use the new scheme. Documented residual risk; no data migration in this phase.
- **Size enforcement**: pre-check `Content-Length` header (reject > ~5.2 MB before parsing) AND `file.size` after `formData()` parse (reject > 5 MB → 413). Note: `request.formData()` fully buffers the body — acceptable for the 5 MB cap; the disk-write path is capped regardless (disk-fill vector closed at write).
- **TEST-05**: no Vitest (developer rejected infra) — standalone `scripts/upload-security-test.mjs` (tsx) like Phase 3: Part A pure-unit on the validator; Part B live HTTP smoke when a dev server is up (401/403/400/413/200 + static-URL 404 + nosniff header). Exit 0/1; npm script `verify:upload-security`.

## Task 1 — Magic-byte validation lib (SEC-10) + .gitignore

Create `lib/file-validation.ts` (server-only, no imports from next — pure Node):

```ts
import { Buffer } from "node:buffer";

export type DetectedImageType = "jpeg" | "png" | "webp";

export const MAX_UPLOAD_BYTES = 5 * 1024 * 1024; // 5 MB
export const MAX_CONTENT_LENGTH_BYTES = MAX_UPLOAD_BYTES + 200 * 1024; // multipart overhead allowance

const PNG_MAGIC = Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]);

/**
 * Detect image type from magic bytes. Returns null for anything that is not
 * JPEG/PNG/WebP (including SVG — no matching magic) (SEC-10).
 */
export function detectImageType(buffer: Buffer): DetectedImageType | null {
  if (buffer.length >= 3 && buffer[0] === 0xff && buffer[1] === 0xd8 && buffer[2] === 0xff) {
    return "jpeg";
  }
  if (buffer.length >= 8 && buffer.subarray(0, 8).equals(PNG_MAGIC)) {
    return "png";
  }
  if (
    buffer.length >= 12 &&
    buffer.toString("ascii", 0, 4) === "RIFF" &&
    buffer.toString("ascii", 8, 12) === "WEBP"
  ) {
    return "webp";
  }
  return null;
}

/** Map detected type → canonical file extension and Content-Type. */
export const IMAGE_EXT_BY_TYPE: Record<DetectedImageType, string> = {
  jpeg: "jpg",
  png: "png",
  webp: "webp",
};
export const IMAGE_CONTENT_TYPE_BY_EXT: Record<string, string> = {
  jpg: "image/jpeg",
  png: "image/png",
  webp: "image/webp",
};
```

## Task 3 — Authenticated serve route (SEC-13) + client mapping

Create `app/api/assets/images/[name]/route.ts`:

```ts
// GET /api/assets/images/[name] - Serve uploaded asset image (authenticated only, SEC-13)
import { NextRequest, NextResponse } from "next/server";
import { readFile } from "fs/promises";
import { join, resolve } from "path";
import { requireUser } from "@/lib/security";
import { IMAGE_CONTENT_TYPE_BY_EXT } from "@/lib/file-validation";

const UPLOAD_ROOT = join(process.cwd(), "uploads", "assets");
// UUID + allowlisted extension only — path-traversal is structurally impossible.
const NAME_PATTERN = /^[a-f0-9-]{36}\.(jpg|png|webp)$/;

export async function GET(_request: NextRequest, { params }: { params: Promise<{ name: string }> }) {
  const { user, response } = await requireUser();
  if (response) return response;
  const { name } = await params;
  if (!NAME_PATTERN.test(name)) return new NextResponse("Not found", { status: 404 });
  const filePath = resolve(UPLOAD_ROOT, name);
  // Belt-and-braces: resolved path must stay under the upload root.
  if (!filePath.startsWith(resolve(UPLOAD_ROOT))) return new NextResponse("Not found", { status: 404 });
  try {
    const data = await readFile(filePath);
    const ext = name.split(".").pop()!;
    return new NextResponse(data, {
      status: 200,
      headers: {
        "Content-Type": IMAGE_CONTENT_TYPE_BY_EXT[ext],
        "Content-Disposition": `inline; filename="${name}"`,
        "X-Content-Type-Options": "nosniff",
        "Cache-Control": "private, max-age=3600",
      },
    });
  } catch {
    return new NextResponse("Not found", { status: 404 });
  }
}
```

Notes:
- `requireUser()` (authenticated only — GET reads follow the Phase 2 matrix; proxy.ts deny-by-default protects `/api/*` automatically, including anonymous 401).
- Content-Type from validated extension; `inline` Content-Disposition; `nosniff` (SEC-13).
- The `user` from the destructure is unused — keep `const { user, response }` for consistency OR `const { response } = await requireUser()` — use `{ response }` (no unused var).
