Vitest infrastructure and the first auth unit tests land here.

## Risks & Dependencies

- **R1 (module-load throw in tests):** Every test importing lib/auth (directly or via the register route) needs JWT_SECRET stubbed BEFORE the import. The env-missing test intentionally does the opposite. Keep the stubEnv/resetModules discipline per-file — a missing stub surfaces as an opaque "Missing required environment variable" failure.
- **R2 (bcrypt cost):** hashPassword (12 rounds) runs in register.test.ts (~0.5s). Acceptable; do not mock bcrypt (that would weaken the test's fidelity).
- **R3 (tsc on test files):** If the project tsconfig does not include tests/, `npx tsc --noEmit` may not type-check them — note it in the SUMMARY rather than adding config churn; vitest still type-checks via its own transform at run time.
- **Dependencies:** Requires 01-02 (rewritten lib/auth with parseClaims/assertUser/bumpTokenVersion, register route EMPLOYEE literal) and 01-01 (env.ts, aligned packages). This plan is the phase's final gate — `npm run test` green is success criterion 5 of the ROADMAP.
