<objective>
Lay the security foundation for Phase 1: a fail-fast environment guard, the tokenVersion schema field, Prisma CLI/client alignment, and the deny-by-default request gate.

Purpose: Every later hardening step (pinned tokens, typed identity, revocation) compiles and runs only on top of this substrate — the regenerated Prisma client must expose `User.tokenVersion`, the proxy must already block anonymous traffic, and `JWT_SECRET` must be a real env value before the app is allowed to boot.
Output: `lib/env.ts`, `prisma/schema.prisma` (tokenVersion), aligned `package.json`/lockfile, a working `.env`, rewritten `proxy.ts`, guarded `app/(authenticated)/layout.tsx`.
</objective>

## Phase Goal

Users get trustworthy sessions — the app fails fast without a JWT secret, tokens are verified with pinned issuer/audience/algorithm/jti and revocable via tokenVersion, self-registration can never elevate a role, and identity is typed so the `user.id` class of bug dies at compile. Vitest infrastructure and the first auth unit tests land here.

**Mode:** mvp

## Requirements

This plan addresses: **SEC-01** (fail-fast env guard foundation), **SEC-04** (tokenVersion schema), **SEC-05** (deny-by-default proxy + layout guard), **DATA-02** (Prisma CLI/client alignment).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client → proxy | untrusted request crosses here; proxy decides gate (allow-list vs 401/302) |
| proxy → page routes | valid stateless token required; handler/layout re-verifies (defense in depth) |
| env/config → lib/env.ts | JWT_SECRET availability is asserted at module load, never defaulted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | lib/env.ts requireEnv | critical | mitigate | Module-load throw when JWT_SECRET unset; no default string anywhere; lib/auth.ts (plan 01-02) consumes it; jose additionally rejects HMAC keys < 32 bytes |
| T-01-02 | Tampering | .env creation | medium | mitigate | JWT_SECRET generated via crypto.randomBytes(32); .env confirmed gitignored (`git check-ignore`); connection strings sourced from shell/developer, never invented |
| T-01-03 | Spoofing | proxy.ts PUBLIC_PATHS | high | mitigate | Exact Set membership for public routes (prefix matching would open lookalikes); `startsWith("/api")` used only for 401-vs-redirect choice; print page already self-guards so inversion is behavior-neutral for it |
| T-01-04 | Tampering | proxy.ts header plumbing | low | mitigate | x-user-id/x-user-role injection deleted (no consumer exists); handlers re-derive identity via getCurrentUser |
| T-01-05 | Tampering | middleware-only auth bypass (CVE-2025-29927 class) | high | mitigate | Proxy is a gate only — every handler/layout re-verifies via getCurrentUser(); layout redirect added as backstop; revocation stays out of the proxy by design |
| T-01-06 | Information Disclosure | requireEnv error message | low | accept | Message names the variable only, no secret material; dev-facing failure by design |
| T-01-07 | Denial of Service | prisma db push / generate | low | accept | Additive column with @default(0) on a dev DB; CLI ops idempotent; no data loss path |
