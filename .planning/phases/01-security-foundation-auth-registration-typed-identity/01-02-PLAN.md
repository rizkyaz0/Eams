<objective>
Harden the auth core: fail-fast secret, pinned token issuance/verification with jti, typed identity that kills the `user.id` bug class at compile time, tokenVersion-based revocation, and registration that can never elevate a role.

Purpose: This is the heart of Phase 1 — it turns forgeable sessions (fallback secret) into pinned, revocable, typed sessions, and closes the live privilege-escalation vector in the public register route.
Output: rewritten `lib/auth.ts`, fixed `register`/`login`/`users/[id]` routes, new `logout-all` route, two `user.id` bug fixes.
</objective>

## Phase Goal

Users get trustworthy sessions — the app fails fast without a JWT secret, tokens are verified with pinned issuer/audience/algorithm/jti and revocable via tokenVersion, self-registration can never elevate a role, and identity is typed so the `user.id` class of bug dies at compile. Vitest infrastructure and the first auth unit tests land here.

**Mode:** mvp

## Requirements

This plan addresses: **SEC-01** (fail-fast secret wiring), **SEC-02** (registration role pinning), **SEC-03** (pinned iss/aud/alg/jti), **SEC-04** (tokenVersion revocation + logout-all + password-change bump), **BUG-01** (typed identity, no index signature, two live bug-site fixes).

  <action>
Rewrite `lib/auth.ts` in place (keep the existing file structure and JSDoc conventions; hand-written style: double quotes, semicolons, 2-space indent). Do NOT add `"use server"` and do NOT import `server-only`. Repo constraint: no new `any`.
1. Secret (SEC-01): delete the module-scope fallback line — the env read with the `||` default string at the top of the file — and replace it with `const JWT_SECRET = requireEnv("JWT_SECRET");`, importing `requireEnv` from `@/lib/env` (created in 01-01). No fallback constant anywhere; a missing secret throws at module load, which fails `next build`, `next dev`, and `next start` for every server module that imports this file.
2. Add constants `TOKEN_ISSUER = "eams"` and `TOKEN_AUDIENCE = "eams-web"`.
3. `JWTPayload`: add `tokenVersion: number`. DELETE the index-signature line — the last interface member (the one currently labeled as required for jose compatibility). The strict interface is the BUG-01 mechanism: `user.id` must no longer compile anywhere. Do not re-add it, and do not make the interface extend jose's JWTPayload type (that trick re-imports the index signature).
4. Add `parseClaims(value: unknown): JWTPayload | null` — runtime claim validator: reject non-objects; require userId/email/fullName to be strings, tokenVersion to be a number, and role to be a string that is a member of the UserRole enum. Returns the value as JWTPayload on success, null otherwise. Signature validity is not claim validity — every verified payload goes through this.
5. `generateToken`: keep the signature; sign with `.setProtectedHeader({ alg: "HS256" })`, `.setIssuer(TOKEN_ISSUER)`, `.setAudience(TOKEN_AUDIENCE)`, `.setJti(randomUUID())` (import `randomUUID` from `node:crypto`), `.setIssuedAt()`, `.setExpirationTime("7d")`. jose's own JWTPayload type carries an index signature, so the strict payload needs exactly ONE controlled cast at this boundary — `{ ...payload } as JoseJWTPayload` with `import type { JWTPayload as JoseJWTPayload } from "jose"`. No casts anywhere else in the codebase.
6. `verifyToken` (SEC-03): verify with `jwtVerify<JWTPayload>(token, SECRET_KEY, { issuer: TOKEN_ISSUER, audience: TOKEN_AUDIENCE, algorithms: ["HS256"] })`, route the verified payload through `parseClaims`, and keep the existing `catch -> return null` contract (proxy.ts and getCurrentUser depend on null-on-failure). verifyToken stays STATELESS — no Prisma access in this function, ever.
7. `getCurrentUser` (SEC-04): after `verifyToken` succeeds, do a fresh-DB revocation check: `db.user.findUnique({ where: { id: payload.userId }, select: { tokenVersion: true } })` (import `db` from `@/lib/db`). If the user row is missing or `user.tokenVersion !== payload.tokenVersion`, return null (revoked/stale token -> 401 at the handler boundary). Otherwise return the payload. The revocation check lives HERE — never in verifyToken (proxy stays DB-free).
8. New exports:
   - `assertUser(): Promise<JWTPayload>` — `const user = await getCurrentUser(); if (!user) throw new Error("Unauthorized"); return user;` (throw contract copied from lib/actions/bast-actions.ts).
   - `getUserIdentity(user: JWTPayload): { userId: string; email: string; role: UserRole; fullName: string; tokenVersion: number }` — returns exactly those five fields.
   - `bumpTokenVersion(userId: string): Promise<void>` — `db.user.update({ where: { id: userId }, data: { tokenVersion: { increment: 1 } } })`.
9. Keep unchanged: `hashPassword` (bcrypt 12 rounds), `verifyPassword`, `setAuthCookie`, `clearAuthCookie`, `hasRole`, `ROLE_HIERARCHY`, `hasMinimumRole`. Add JSDoc to every exported function, including the new ones.
Commit: `feat(01): harden lib/auth — fail-fast secret, pinned tokens, typed identity, tokenVersion`

## Risks & Dependencies

- **R1 (interface break):** Adding tokenVersion to JWTPayload breaks login/register compile until Task 2; removing the index signature breaks the two bug sites until Task 3. The plan is ordered so tsc is only green at the END of Task 3 — do not "fix" intermediate failures by re-adding the signature or skipping the version claim (that would resurrect BUG-01/SEC-04).
- **R2 (proxy statelessness):** verifyToken must stay DB-free. If a future change adds a DB read to verifyToken, the 01-01 proxy gate silently loses its fast-path property — the getCurrentUser split is load-bearing.
- **R3 (existing sessions):** Every currently issued cookie lacks iss/aud/jti/tokenVersion — after this plan, all existing sessions are rejected (forced re-login once). Intended consequence per research; no data migration.
- **R4 (.env rename check):** The fail-fast proof requires temporarily renaming .env. Restore must be unconditional (finally-style) — losing .env breaks every subsequent plan.
- **Dependencies:** Requires 01-01 (lib/env.ts, regenerated Prisma client with tokenVersion, .env). Plan 01-03's tests import this plan's rewritten lib/auth and register route.
